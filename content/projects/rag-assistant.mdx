## 專案概述

這是一個用 **Python + FastAPI** 打造的**檢索增強生成（RAG）微服務**：上傳文件（PDF / Word / txt / md）後，可以用自然語言提問，AI 會**只根據文件內容**回答，並標出引用來源；資料裡找不到答案時直接說「找不到」，而不是憑空編造。

它有一個內建的問答介面可直接操作，也提供 JSON API 供其他系統（例如我的 Next.js 前台）呼叫。

而這個 Demo 有個特別的設計：**它的知識庫就是「我的技術履歷」**。所以你打開 Demo 等於在跟我的 **AI 分身**對話——可以直接問它「他會 Python 嗎？」「做過哪些專案？」「他怎麼做專案的？」，它會根據我的真實履歷回答。

## 為什麼做這個

我想在作品集裡明確補上 **Python 與 LLM / RAG** 的能力，對準 AI 工程師職缺。比起寫一個玩具範例，我選擇做一個**完整、能部署、能互動**的微服務，並刻意處理部署與穩定性的真實細節。

順帶一個我喜歡的巧思：把履歷本身變成知識庫，讓這個技術專案**同時也是在介紹我自己**——每一次互動都在展示「RAG 能做什麼」與「我是誰」。

## RAG 是什麼、怎麼運作

RAG（Retrieval-Augmented Generation，檢索增強生成）的重點，是讓大型語言模型**根據你提供的私有資料**回答，而不是只靠它自己的訓練知識——藉此降低幻覺、並能引用來源。

```
上傳文件 → 解析文字 → 切塊 → embedding 轉成向量 → 存入向量庫
提問 → 問題轉向量 → 向量庫找最相關的段落 → 連同問題交給 LLM → 生成答案 + 來源
```

## 技術架構

| 層面 | 技術 |
|------|------|
| Web 框架 | FastAPI（JSON API + 內建靜態問答介面） |
| 文件解析 | pypdf、python-docx |
| Embedding | fastembed（ONNX 本機推論，中文模型 `bge-small-zh`） |
| 向量檢索 | numpy cosine 相似度（demo 規模足夠；可換 FAISS 擴充） |
| LLM | Google Gemini（`google-genai` SDK，`gemini-2.5-flash-lite`） |
| 部署 | Docker（多階段建置、預載模型）+ Render |

## 幾個值得一提的技術細節

### 1. 為什麼選 fastembed 做 embedding
Render 免費方案只有 **512MB 記憶體**。一般 PyTorch + transformers 的 embedding 模型動輒吃掉好幾百 MB、還要下載大檔，容器很容易 OOM。我改用 **fastembed**：以 ONNX 在本機推論、不需 GPU、記憶體佔用小，並選用對中文檢索友善的 `bge-small-zh` 模型。Docker build 時就**預先下載模型**，讓冷啟動更快。在資源受限的免費環境做出務實取捨，是這個專案的一個重點。

### 2. 防幻覺：只依文件回答、找不到就明說
LLM 的 system prompt 嚴格限制「只能根據檢索到的段落回答，找不到就直說找不到、不要硬湊」，每則回答還會附上**引用來源**與實際檢索到的段落。對 AI 應用來說，「**知道自己不知道**」往往比多答幾句更重要——尤其當它代表我回答時，寧可說「資料裡沒有」也不該編造假經歷。

### 3. 對冷啟動與額度限制的韌性
免費容器冷啟動的瞬間、或外部 API 短暫抖動時，第一個請求常會失敗。我在 LLM 呼叫外層加上**自動重試**與**壞連線自動重建**，並對所有失敗做**優雅降級**——就算 LLM 暫時不可用，使用者仍能看到檢索到的相關段落，而不是看到一個錯誤頁。我也依免費額度的實際限制，選用每日免費額度較高的 `gemini-2.5-flash-lite`。

### 4. 檢索品質的調校
一份履歷被切成多個段落後，單一問題若只取前幾名，容易漏掉關鍵段落（例如問「他會 Python 嗎」卻沒撈到技術棧那段）。我調整了切塊大小與檢索數量，平衡「召回率」與「精準度」，讓技術棧、專案這類關鍵資訊能被穩定取出。

### 5. 前端的小細節
問答介面是純 vanilla JS。我處理了兩個容易被忽略的體驗問題：**中文輸入法用 Enter 確認選字時不應誤觸送出**，以及**送出途中鎖住、避免重複提問**。

## 把它變成「AI 分身」

技術做完後，我把知識庫換成自己的技術履歷，並把介面與 LLM 角色設定改寫成「以第三人稱代我回答、不編造經歷」。於是同一套 RAG 系統，就成了一個會替我說話的互動作品：面試官不必讀完整份履歷，直接問它就好。

考量到 Demo 是公開的，我也對履歷做了**去識別化**（移除電話、完整住址等私人資料），只保留專業相關的內容。

## 成果

- 一個**端到端可運作的 RAG 微服務**：上傳 → 檢索 → 作答 → 標來源，全部跑通並部署上線。
- 在 **512MB 免費容器**裡完成，示範了資源受限下的工程取捨。
- 具備**防幻覺、引用來源、優雅降級**等正式系統會在意的特性。
- 化身為可即時對話的 **AI 分身**，是作品集裡唯一能「直接跟它互動」的案例。
- 原始碼公開於 GitHub，含完整 README 與 Docker / Render 部署設定。
